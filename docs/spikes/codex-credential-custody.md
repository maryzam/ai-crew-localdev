# Codex credential custody

An isolated Codex home used a custom Responses model provider whose `env_key` supplied a random placeholder and whose base URL pointed to a local host proxy. The proxy accepted only that placeholder, replaced it with the access token from the host's native ChatGPT login cache, added the host account ID, and forwarded the genuine Codex CLI request to the ChatGPT Codex backend. The proxy did not print or persist model request content or credentials.

One prompt completed with HTTP 200 on each installed Codex CLI version, 0.162.1 and 0.163.0. Each CLI sent one `/backend-api/codex/responses` request with the placeholder. Scanning the isolated Codex home after each run found neither the host access token nor the host refresh token. A direct backend request using a random placeholder returned HTTP 401.

The host Codex app-server's documented `account/read` request with `refreshToken: true` rotated both access and refresh tokens in the host login cache. A later placeholder-proxy prompt completed with HTTP 200 on 0.163.0 using the refreshed host state. These checks used genuine tokens issued by native ChatGPT sign-in; the placeholders were random values, not fabricated OAuth tokens.

[`internal/modelproxy`](../../internal/modelproxy) now enforces this model boundary. The Codex handler accepts only `/backend-api/codex/models` and `/backend-api/codex/responses`, validates the run placeholder, supplies the host account ID, and writes evidence before forwarding. A failed evidence write latches the proxy closed. The host credential source requires an owner-only native `auth.json`, reads its access-token expiry, and uses the native Codex app-server to refresh before expiry or after an upstream 401. Failure to read or refresh the host login refuses the model request. A streaming redactor prevents an upstream response from echoing the host access token into the container.

`AI_CREW_CODEX_AUTH_FILE=<host auth.json> AI_CREW_CODEX_VERSIONS="0.162.1 0.163.0" make codex-proxy-compat` runs the genuine CLIs in rootless Podman with `--network none`, a mounted run socket, and one persistent isolated Codex home. The check deliberately refreshes the host login once, verifies that both tokens rotate, then verifies live model responses across versions, provider rejection of the copied placeholder, and absence of host tokens from the agent home and evidence. Focused unit tests cover unsafe auth files, refresh and audit failure, route and credential refusals, and streamed credential redaction. This proves the pivot's model-credential Proof of alignment item for the tested versions.

`ai login codex` and `ai up` have not yet been wired to this package. The login flow must choose native file credential storage in a broker-only volume; arbitrary future CLI upgrades and optional Codex endpoints still need their compatibility checks.

[OpenAI's authentication documentation](https://learn.chatgpt.com/docs/auth) describes native ChatGPT login caching and automatic refresh. [The gateway documentation](https://learn.chatgpt.com/docs/enterprise/sign-in-with-chatgpt-through-a-gateway) supports forwarding genuine Codex requests through a gateway, but its documented configuration sends the real ChatGPT token from the CLI. The exact host-side substitution tested here is not explicitly documented there. [Sign in with ChatGPT for open-source apps](https://developers.openai.com/siwc/token-sharing-open-source) provides a separately registered application flow. Confirm the applicable terms for AI Crew's host proxy before treating Codex as a supported v0 agent.
