# ADR 0018: Up Experience Spine

## Status

Accepted

## Context

`ai-agent up` is the primary entrypoint, but it is an imperative passthrough script with no boundary between doing work and showing the operator what happened. It wires `devcontainer` and podman child stdout/stderr straight to the terminal, interleaves ad-hoc `fmt.Fprintf` progress lines through a CLI-side switch, aborts on the first error, and treats the container as fire-and-forget. Five first-use failures all trace to that one missing boundary: the podman build log drowns the session, ai-agent's own lines have no structure or namespace to distinguish them, internal detail and opaque child exit codes leak into the operator view (for example `agent login status: exit status 127` from an auth probe run where no agent CLI exists), the shell lands at the mounted workspace root instead of a repository, and a recoverable pre-flight failure reads as "start over" because the fix path and the still-running container are buried in passthrough noise. The tool's purpose is invisible governed flows; raw subprocess noise and untyped failures are the opposite of that.

## Decision

Introduce a presentation and orchestration spine for `up` so that domain packages emit semantic events and a single operator-facing boundary decides how they render. The spine has four parts. A single reporter owns every human-facing byte: step glyphs, an `ai-agent` namespace prefix, phase spacing, warning and error styling, and color gated on an interactive terminal and `NO_COLOR`; presentation types never enter `internal/runtime/uphost` or `internal/runtime/devcontainer`. A capturing command runner sends non-interactive child stdout and stderr to a per-run log under the data directory, shows a curated step line, and surfaces only a bounded tail plus the log path on failure or under `--verbose`; the interactive shell alone stays wired to the real terminal. Typed diagnostics carry a plain-language cause and a remediation that is either informational or repairable, keeping raw exit codes and stack traces in the log and never in the default view; this generalizes the PEM permission repair from ADR-era onboarding into one reusable failure shape. The workspace and container become a durable, re-enterable resource so failure never implies rebuild, and the orchestrator knows the target repository so it can land the operator inside it with the next action staged.

The reporter and capturing runner land first as the foundation that dissolves the noise, structure, and leaked-exit-code failures. Typed-diagnostic in-place repair (including switching an SSH origin to HTTPS at the point of refusal), idempotent and resumable `up`, and repository-aware landing follow as increments against the same event contract. Auto-repair only ever fixes ergonomics: it never relaxes governance, never adds a resource to policy, and never weakens a scope to recover, so security diagnostics stay informational and fail closed. The raw child output remains available behind `--verbose` and the log; the default is curated, not lossy. Remaining subprocess emitters migrate onto the capturing runner incrementally rather than in one sweep.

## Consequences

`up` output becomes readable: podman and devcontainer noise moves to a log the operator opens on demand, ai-agent's own steps are visually distinct, and failures explain themselves with actions instead of exit codes. Adding a capability becomes adding a step that emits events and a diagnostic, not threading new print statements and error handling through several files, so the entrypoint can converge toward launching directly into the governed working state without a rewrite per capability. The event contract is now load-bearing and is covered by tests, so changing an event's shape is a deliberate change. The first increment leaves the host and configuration readiness prompts on their existing direct output; they migrate onto the reporter as later increments, so output is fully curated only once that migration completes.
